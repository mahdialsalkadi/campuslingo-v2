## Rules

1. One row per decision. Keep it to one line. No ADR is required.
2. A decision may choose an implementation approach, ordering, internal representation, or a bounded protocol parameter already owned by an open gate.
3. A decision may NOT change an approved numeric contract, formula, predicate, cap, register ID, or milestone ownership. If it would, set `Status = ESCALATE` and stop; that requires an explicit spec revision with a §0.1 superseded entry.
4. Never renumber canonical IDs. Never compress or delete specification sections.
5. Status values: `DECIDED` | `OPEN` | `DEFERRED` | `ESCALATE`.
6. `Touches (§/ID)` lists the clauses/register IDs affected by each row so rule 3 can be checked without assuming that a decision changes those clauses. `DECIDED` means the implementation interpretation is selected, not that code, migrations, or gate evidence already exist.
7. The request used `DEC-003` for two different topics. Preserve `DEC-003` for `AXIOM_PACK` card/FSRS identity and record the accommodation representation as `DEC-010`; no existing ID is renumbered or reused.
